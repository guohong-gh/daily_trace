# 测试指南

本文说明「日迹」的测试分层、当前用例基线、常用命令、模拟器走查方法与排障。测试不是“跑绿即可”，每个批次都要同时回答：规则是否被穷举、数据库是否真实往返、用户路径是否在 AVD 上走通。

> 基线：2026-11-09，`versionName 1.0.0` / `versionCode 1` / DB v6。
> 当前 JVM 测试：**269 个用例，39 个测试类，全部通过**（以 `.\scripts\verify.ps1` 最近一次输出为准）。

## 一、测试分层

| 层级 | 工具 | 覆盖对象 | 是否门禁 |
|------|------|----------|----------|
| 纯逻辑单测 | JUnit4 | 时间、打卡计划、补卡策略、筛选、统计、报告、CSV、提醒时间、每日汇总、组件数据 | 是 |
| 数据库/流程测试 | Robolectric + 内存 Room | Repository、DAO、备份往返、批量操作、诊断修复、ViewModel 编排 | 是 |
| 静态检查 | Android Lint | 权限、API 级别、资源、Compose/Manifest 问题 | 是（0 error） |
| release 构建 | Gradle + R8 | 混淆/压缩后能否构建与启动 | 是 |
| 模拟器手工走查 | AVD + adb | 真实交互、通知、提醒、组件、布局、截图 | 是（批次验收） |
| UI 自动化 | Compose UI Test | 当前未建设 | 否 |

`app/src/androidTest/` 只有模板 `ExampleInstrumentedTest.kt`，不参与门禁，也不要在汇报中把它算作覆盖。

## 三、运行命令

### 3.1 全量 JVM 测试

```powershell
.\gradlew.bat testDebugUnitTest
```

结果：

- HTML 报告：`app\build\reports\tests\testDebugUnitTest\index.html`
- XML：`app\build\test-results\testDebugUnitTest\TEST-*.xml`

统计用例数：

```powershell
$files = Get-ChildItem app\build\test-results\testDebugUnitTest\TEST-*.xml
$total = ($files | ForEach-Object {
    ([xml](Get-Content -LiteralPath $_.FullName -Raw)).testsuite.tests
} | Measure-Object -Sum).Sum
"total = $total"
```

### 3.2 只跑一个测试类 / 一个方法

```powershell
.\gradlew.bat testDebugUnitTest --tests "com.gh.daily_trace.domain.stats.StatsCalculatorTest"
.\gradlew.bat testDebugUnitTest --tests "com.gh.daily_trace.domain.stats.StatsCalculatorTest.`连续打卡不因今天未打卡中断`"
```

类名必须写全限定名；方法名含中文时用反引号包裹。若终端对中文支持不佳，优先只跑类，减少输入问题。

### 3.3 强制重跑

```powershell
.\gradlew.bat testDebugUnitTest --rerun-tasks
```

### 3.4 lint

```powershell
.\gradlew.bat lintDebug
```

报告：

- `app\build\reports\lint-results-debug.html`
- `app\build\reports\lint-results-debug.txt`

门禁要求 **0 errors**。当前基线为 0 errors / 0 warnings（M13-3 起）；新增 warning 必须在批次说明中解释，能修则修。

### 3.5 release 构建

```powershell
.\gradlew.bat assembleRelease
```

产物：`app\build\outputs\apk\release\app-release.apk`

release 开启 R8，使用自建 keystore 正式签名（参数来自本机 `keystore.properties`），详见 `docs/发布流程.md`。

### 3.6 一键门禁

```powershell
.\scripts\verify.ps1
```

脚本依次执行：

1. `testDebugUnitTest`
2. `lintDebug`
3. `assembleRelease`
4. 解析 JUnit XML、lint 摘要与 APK 大小

输出为英文，避免 Windows PowerShell 5.1 中文控制台乱码。任一阶段失败或 lint error > 0 时脚本以非 0 退出。成功时输出类似：

```text
================ VERIFY SUMMARY ================
Tests   : 269 total, 269 passed, 0 failed, 0 errors, 0 skipped
Lint    : 0 errors, 0 warnings
Release : 2231460 bytes (2.13 MB)
APK     : ...\app\build\outputs\apk\release\app-release.apk
================================================
VERIFY PASSED
```

（上面的数字为 1.0.0 基线示例，实际以本次输出为准。）

## 四、写测试的约定

### 4.1 纯逻辑

- 固定时间：使用 `DayClock(zone, startOfDayHour, weekStart, clock)` 或显式 `epochDay`，不要在断言里依赖 `LocalDate.now()`。
- 固定时区：测试统一 `Asia/Shanghai`，需要跨时区时显式传 `ZoneId`。
- 命名用中文反引号描述行为，例：``fun `凌晨4点前属于前一天`()``。
- 一个用例只断言一个规则；边界值（0、1、上限、跨月、跨年、闰年、空列表）优先。
- 统计测试同时覆盖“期望日口径”和“实际完成口径”，不要只测一个百分比。

### 4.2 Robolectric / Room

- 使用内存数据库，测试结束关闭，避免污染本机 `daily_trace.db`。
- 备份往返测试要覆盖：回收站、可空字段、枚举、列表、旧备份缺字段的默认值。
- 迁移测试应使用旧版本 schema 或旧库副本；不要只测“新库能打开”。
- ViewModel 测试使用可控协程调度器；不要在测试里等待真实 300ms 防抖。
- 批量操作测试要验证“只影响所选”，尤其是记录备注、删除、选项归档/回收站。

### 4.3 新增测试的时机

- 改 `domain/`：先加/改纯逻辑测试，再改实现。
- 改 DAO/Repository：加真实数据库往返测试。
- 改 ViewModel 编排：加流程测试（批量、补卡、计划、筛选应用）。
- 改 UI 布局：无自动化时，用 AVD 走查 + 截图；若涉及可计算断点，抽纯函数测试（如 `WindowSizeTest`）。
- 改 schema / 备份 / CSV：必须补迁移、兼容或格式测试，详见 `AGENTS.md`。

## 五、模拟器走查

### 5.1 环境

- 默认 AVD：`Medium_Phone_API_37.0`（1080×2400）。
- `adb` 不在 PATH 时使用完整路径：
  `%LOCALAPPDATA%\Android\Sdk\platform-tools\adb.exe`。
- 多设备时所有命令必须带 `-s emulator-5554`，避免装到其他设备。
- 走查前确认工作区没有未提交的业务改动；走查产生的演示数据不要提交。

### 5.2 启动与连接

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -list-avds
Start-Process "$env:LOCALAPPDATA\Android\Sdk\emulator\emulator.exe" -ArgumentList "-avd Medium_Phone_API_37.0"
& $adb devices
```

等待 `device` 状态后安装：

```powershell
& $adb -s emulator-5554 install -r app\build\outputs\apk\release\app-release.apk
& $adb -s emulator-5554 shell am start -n com.gh.daily_trace/.MainActivity
```

### 5.3 截图

PowerShell 5.1 直接用 `>` 重定向二进制会损坏 PNG。使用“设备内截图 + pull”：

```powershell
New-Item -ItemType Directory -Force docs\截图 | Out-Null
& $adb -s emulator-5554 shell screencap -p /sdcard/daily_trace_shot.png
& $adb -s emulator-5554 pull /sdcard/daily_trace_shot.png docs\截图\批次-01-主题.png
& $adb -s emulator-5554 shell rm /sdcard/daily_trace_shot.png
```

命名规则：`<批次>-<序号>-<主题>.png`，例如 `m12-05-recent-frequent.png`。已有验收截图不覆盖。

### 5.4 常用系统设置

```powershell
# 字体缩放（1.0 为默认）
& $adb -s emulator-5554 shell settings put system font_scale 1.3
& $adb -s emulator-5554 shell settings put system font_scale 1.0

# 平板尺寸（示例：2560×1600，density 320 ≈ 1280×800dp）
& $adb -s emulator-5554 shell wm size 2560x1600
& $adb -s emulator-5554 shell wm density 320
& $adb -s emulator-5554 shell wm size reset
& $adb -s emulator-5554 shell wm density reset

# 关闭动画，便于稳定截图
& $adb -s emulator-5554 shell settings put global window_animation_scale 0
& $adb -s emulator-5554 shell settings put global transition_animation_scale 0
& $adb -s emulator-5554 shell settings put global animator_duration_scale 0
```

走查结束必须恢复 `wm size`、`wm density`、`font_scale` 与动画设置。

### 5.5 权限

```powershell
# Android 13+ 通知权限
& $adb -s emulator-5554 shell pm grant com.gh.daily_trace android.permission.POST_NOTIFICATIONS

# 精确闹钟（模拟器上可显式允许；正式用户需在系统设置授权）
& $adb -s emulator-5554 shell appops set com.gh.daily_trace SCHEDULE_EXACT_ALARM allow
```

不要假设权限一定已授予；走查记录要写明“已授权 / 未授权 / 降级”的实际状态。

### 5.6 提醒、通知、组件核对

```powershell
& $adb -s emulator-5554 shell dumpsys alarm | Select-String "com.gh.daily_trace"
& $adb -s emulator-5554 shell dumpsys notification | Select-String "com.gh.daily_trace|打卡提醒|今日打卡汇总"
& $adb -s emulator-5554 logcat -d | Select-String "DailySummaryWorker|FATAL EXCEPTION|daily_trace"
```

记录：

- 闹钟数量与下次触发时间；
- 通知渠道（默认 / 安静 / 每日汇总）；
- 暂停期间是否还有系列闹钟；
- 组件打卡后数据库中的 `source=WIDGET`（如能安全拉库）。

### 5.7 清空演示数据

优先用 App 内备份恢复或删除选项。确实要清空时：

```powershell
& $adb -s emulator-5554 shell pm clear com.gh.daily_trace
```

`pm clear` 会删除应用全部私有数据，不可恢复；执行前确认已有可恢复备份，且不是用户真实数据。

## 七、常见测试问题

| 现象 | 原因 | 处理 |
|------|------|------|
| `Unsupported class file major version` / JDK 相关错误 | 启动 Gradle 的 JDK 与基线不符 | 用 JDK 23 启动；daemon 按 `gradle/gradle-daemon-jvm.properties` 使用 JDK 25 |
| `SDK location not found` | 缺 `local.properties` | 在根目录配置 `sdk.dir`，不要提交 |
| Robolectric 报 `jdk.internal.access` 不可访问 | JDK 25 模块访问限制 | 项目已在 `build.gradle.kts` 加 `--add-exports`；不要删除 |
| 单测在本地过、换机器失败 | 时区 / 当前时间 / locale 依赖 | 固定 `Clock`、`ZoneId`、`Locale`；不要用真实“今天”做断言 |
| `--tests` 找不到类 | 类名不是全限定名，或方法名转义错误 | 先只跑类；中文方法名用反引号 |
| lint 新增 error | 权限、API 级别、资源引用等 | 看 `lint-results-debug.txt` 定位；不要用全局 suppress 掩盖 |
| `adb` 找不到 | 未加入 PATH | 用完整路径或设置 `$adb` 变量 |
| `adb devices` 显示 unauthorized | 设备未授权 | 在设备上允许 USB 调试；模拟器重启 adb |
| `INSTALL_FAILED_UPDATE_INCOMPATIBLE` | 签名或包名冲突 | 确认同签名；必要时卸载旧包（会丢数据，先备份） |
| 截图全黑 / 打不开 | PowerShell 重定向损坏二进制 | 用 `screencap` + `pull` |
| 通知不出现 | 通知权限 / 渠道被关 / 暂停中 | 检查权限、渠道、`pausedUntil` 与免打扰 |
| 提醒不准 | 无精确闹钟权限或系统省电限制 | 授权精确闹钟；在模拟器上核对 `dumpsys alarm` |
| `verify.ps1` 报 “could not parse lint summary” | lint 报告格式变化或未生成 | 先单独跑 `lintDebug`，确认 txt 报告末尾摘要 |
| 测试数不是 269 | 新增/删除了用例 | 以 XML 汇总为准，并同步本文档与状态文档 |
