# 文档导航

本页是「日迹」（Daily_Trace）全部文档的入口。第一次接触项目时，先按角色选择阅读路径；需要查具体事实时，直接查下方索引。

> 文档基线：2026-10-23，对应 `versionName 1.0.0`、`versionCode 1`、数据库版本 6。
> 文档与代码冲突时，以代码与 `docs/项目状态与计划.md` 的已确认事实为准；冲突按真实实现描述，并集中登记到 `docs/需求差距与验收矩阵.md` 的「允许偏差」表。

## 一、按角色阅读

### 1. 只想使用 App

1. `README.md`：了解项目定位与安装方式。
2. `docs/使用手册.md`：按「入口 / 操作步骤 / 结果 / 注意事项」完成全部日常操作。
3. `docs/常见问题.md`：遇到提醒、备份、统计口径问题时查阅。
4. `docs/隐私与数据安全.md`：了解数据存放位置、权限与备份风险。

### 2. 第一次参与开发

1. `AGENTS.md`：协作硬约束、批次工作流、提交规范、AVD 走查约定。
2. `贡献指南.md`：环境搭建、首次构建、代码约定、提交自查。
3. `docs/架构说明.md`：分层、模块、数据流与关键设计。
4. `docs/测试指南.md`：测试分层、命令、模拟器走查与排障。
5. `docs/数据格式说明.md`：数据库、备份 JSON、CSV 口径。
6. `docs/决策记录.md`：D1–D49 索引与 D50 起的决策全文。

### 3. 准备发版

1. `docs/发布流程.md`：版本号、门禁、构建、装机冒烟与发布检查。
2. `docs/测试指南.md`：确认测试与 AVD 走查要求。
3. `docs/需求差距与验收矩阵.md`：逐项确认验收状态与允许偏差。
4. `docs/项目状态与计划.md`：查看最近批次记录、技术债与待确认问题。

### 4. AI 代理

先读 `AGENTS.md`，再读本页与 `docs/项目状态与计划.md` 的最近批次。不要只根据旧截图或旧文档改代码；任何新决策从 D50 起登记到 `docs/决策记录.md`。

## 三、文档权威顺序

出现表述不一致时，按以下顺序判断：

1. 代码、`AndroidManifest.xml`、`app/build.gradle.kts`、`app/schemas/` 等可执行事实。
2. `docs/数据格式说明.md` 与 `docs/决策记录.md` 中已登记的格式/口径。
3. `docs/项目状态与计划.md` 的已确认事实与最近批次记录。
4. `docs/使用手册.md`、`README.md` 等面向读者的说明。
5. 历史截图与旧批次描述（只证明当时状态）。

如果发现冲突，不要为了“让文档自洽”改业务代码；先记录冲突，再在文档中描述真实实现，并在最终汇报或验收矩阵中列出。

## 四、文档写作规则

- 文档一律使用中文。除 `README.md`、`AGENTS.md` 外，新增文档文件名使用中文。
- `docs/` 下的文档引用截图写相对路径 `截图/xxx.png`；根目录文档写 `docs/截图/xxx.png`。
- 命令统一使用 Windows PowerShell 与 `.\gradlew.bat`，并确保真实可跑。
- 不复制大段历史决策正文。D1–D49 全文在 `docs/项目状态与计划.md`，本页与 `docs/决策记录.md` 只做索引；D50 起写入 `docs/决策记录.md`。
- 新增或改名文档后，同步更新本页、`README.md`、`AGENTS.md` 的文档地图与全库引用。
- 截图按 `<批次>-<序号>-<主题>.png` 命名；已有验收截图不覆盖、不删除。
- 文档不提交 APK、`build/`、`local.properties`、`.idea/`、崩溃日志或真实用户备份。

## 五、常用入口命令

```powershell
.\gradlew.bat testDebugUnitTest   # 单元测试
.\gradlew.bat lintDebug           # 静态检查
.\gradlew.bat assembleRelease     # release 构建（R8，正式签名）
.\scripts\verify.ps1              # 单测 + lint + release 一键门禁
```
