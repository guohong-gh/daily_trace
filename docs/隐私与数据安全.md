# 隐私与数据安全

「日迹」是本地优先的打卡应用：没有账号、没有云同步、没有广告或分析 SDK。唯一的联网行为是启动时与设置页手动触发时，向 GitHub Releases 查询最新版本号，不上传任何本地数据。本文说明数据清单、权限、存放位置、导出与系统备份的实际边界，以及删除、换机和日常使用建议。

> 适用版本：`versionName 1.0.0`、`versionCode 10000`、数据库 v6。
> 本文以代码与 `AndroidManifest.xml` 为准；如果系统厂商的备份、权限或文件管理行为不同，以设备和系统设置为准。

## 一、一句话结论

- 业务数据只写入本机应用私有目录，不会离开设备。
- 唯一的对外请求是向 GitHub 查询版本号：不带设备标识、不带打卡内容，失败时静默。
- 提醒需要通知、精确闹钟和开机重排 3 项权限；联网只需 `INTERNET`；不需要存储、位置、通讯录、相机或麦克风权限。
- 导出的 JSON / CSV 是**明文**，离开应用后由你选择的位置和账号保护。
- 系统云备份 / 设备迁移可能包含应用数据，是否发生由系统与用户设置决定，应用无法单独关闭。
- 卸载或“清除数据”会删除应用私有数据；已经导出的文件不会被应用删除。

## 二、数据清单

| 数据 | 主要内容 | 存放 | 是否进入 JSON 备份 | 是否进入 CSV |
|------|----------|------|--------------------|--------------|
| 打卡选项 | 名称、emoji、颜色、类型、单位、目标值、默认备注、分组、排序、启用 / 归档 / 回收站状态 | Room `check_items` | 是（含回收站） | 仅记录中的名称快照等字段 |
| 打卡记录 | 逻辑日、数值、单位、单次备注、状态、来源、是否补卡、时区、时间戳、选项名称 / 颜色 / 图标快照 | Room `check_records` | 是 | 是 |
| 日期备注 | 每天一条整体备注 | Room `day_notes` | 是 | 否 |
| 分组 | 4 个种子分组的名称、颜色、排序 | Room `groups` | 是 | 否 |
| 提醒 | 时刻、重复方式、星期、免打扰、启用状态 | Room `reminders` | 是 | 否 |
| 筛选视图 | 名称、选项 / 分组范围、匹配逻辑、日期状态 | Room `filter_views` | 是 | 否 |
| 频率规则 | 每天 / 每周几 / 每月几次 / 每周几次 / 自定义、跳过日期 | Room `frequency_rules` | 是 | 否 |
| 设置 | 主题、动态取色、周起始、日起始、时区、日期语言 / 格式、补卡上限、部分完成口径、自动备份、暂停、每日汇总 | Room `app_settings` | 是 | 否 |
| 本机自动备份 | 上述全量 JSON 快照，最多 5 份 | `files/backups/` | 不包含自身 | 否 |
| 崩溃日志 | 版本、设备、Android、线程、堆栈，最多 10 份 | `files/crash_logs/` | 否 | 否 |
| 导出的 JSON / CSV | 用户主动选择位置的文件 | SAF 目标位置 | — | — |

说明：

- 单次打卡备注、日期备注、选项名称都可能包含健康、行程、情绪等敏感信息，请按敏感数据处理。
- 记录保存选项名称 / 颜色 / 图标快照，因此删除或改名选项不会改写历史；这也意味着历史记录仍可能包含已删除选项的旧名称。
- 崩溃日志不包含打卡正文，但可能包含类名、文件路径、设备型号与系统版本。

## 三、权限

| 权限 | 用途 | 触发时机 | 拒绝后的影响 |
|------|------|----------|--------------|
| `POST_NOTIFICATIONS` | 显示打卡提醒、稍后提醒、每日汇总 | Android 13+ 首次需要显示通知时 | 通知不显示；提醒调度仍可能执行但不可见 |
| `SCHEDULE_EXACT_ALARM` | 尽量准点触发提醒 | Android 12+ 在编辑提醒时可引导授权 | 降级为不精确调度，提醒可能延迟数分钟 |
| `RECEIVE_BOOT_COMPLETED` | 开机后恢复提醒与每日汇总 | 系统开机 / 时间或时区变化 / 应用更新 | 重启后提醒可能不再自动恢复，需打开应用重排 |
| `INTERNET` | 向 `api.github.com` 查询最新版本号，跳转 `github.com` 下载页 | 冷启动一次；设置页「检查更新」 | 检查失败，不弹提示、不影响任何功能 |

以上为本应用自声明的 4 项。合并后的 Manifest 还会出现 4 项非自声明权限（见 D58）：

| 来源 | 权限 | 说明 |
|------|------|------|
| `androidx.work:work-runtime` | `WAKE_LOCK`、`ACCESS_NETWORK_STATE`、`FOREGROUND_SERVICE` | WorkManager 调度每日汇总所需；`ACCESS_NETWORK_STATE` 只能读取网络状态，不代表可以联网 |
| AndroidX 自动生成 | `com.gh.daily_trace.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION` | 保护应用内动态注册的 Receiver，仅供本应用使用 |

没有申请：

- `READ_EXTERNAL_STORAGE` / `WRITE_EXTERNAL_STORAGE` / `MANAGE_EXTERNAL_STORAGE`：导出通过系统文件选择器（SAF）按单个 URI 授权，不需要广泛存储权限。
- 位置、通讯录、相机、麦克风、日历、身体传感器、电话状态等权限。

`INTERNET` 的使用边界（见 D59）：

- 只有两处目标：`https://api.github.com/repos/guohong-gh/daily_trace/releases/latest`（读取 `tag_name`）与 `https://github.com/guohong-gh/daily_trace/releases/latest`（用户点「去更新」时交给浏览器）。
- 请求只带固定 `User-Agent`（应用名 + 当前版本）与 `Accept` 头，不带设备标识、账号、打卡内容或任何本地数据。
- 不做应用内下载与安装，不申请「安装未知应用」权限。
- 冷启动检查在后台执行，任何失败（断网、超时、限流、解析异常）只记日志，不弹错误。
- CI 会扫描 `app/src/main/java` 中出现的 http(s) 主机，白名单外即构建失败；这是文本扫描，能拦住写死的域名，拦不住运行时拼接或重定向。

注意：权限边界只约束「日迹」本身；设备上的其他应用、系统备份、云盘同步或 root 工具仍可能读取你主动导出的文件。

## 四、数据存放位置

### 4.1 应用私有目录

在未 root 的设备上，其他普通应用无法直接读取以下目录：

```text
/data/data/com.gh.daily_trace/
  databases/
    daily_trace.db          # Room 数据库（可能伴随 -wal / -shm）
  files/
    backups/
      daily_trace_YYYYMMDD_HHMMSS.json   # 本机自动备份，最多 5 份
    crash_logs/
      crash_YYYYMMDD_HHMMSS_SSS.log      # 崩溃日志，最多 10 份
```

- 本机自动备份在应用启动、退到后台时按间隔检查；「立即备份」忽略开关与间隔。
- 自动备份只保留最近 5 份，超过后删除最旧文件。
- 崩溃日志只保留最近 10 份，可在设置页导出或清除。
- 这些文件随应用卸载或系统“清除数据”一起删除。

### 4.2 应用外部

通过「导出备份」「导出 CSV」「导出崩溃日志」写出的文件位于你通过系统文件选择器指定的位置，例如下载目录、云盘客户端或 U 盘。写入完成后：

- 文件不再受应用私有目录保护；
- 是否被云盘同步、其他应用索引、媒体扫描或他人看到，取决于该位置与系统设置；
- 应用不会保留对这些文件的持续访问权限，也不会自动删除它们。

### 4.3 桌面小组件与通知

- 桌面小组件会在桌面显示今日进度、选项名称和快捷项；桌面是否被他人看到取决于你的环境与锁屏策略。
- 通知会显示选项名称、完成情况或每日汇总数量；锁屏预览、通知历史与悬浮通知由系统设置控制。
- 最近任务预览、系统截图、录屏也可能包含打卡内容；分享截图前请先检查。

## 五、网络与第三方

- 联网仅限更新检查：`api.github.com` 读取最新版本号；其余网络行为（账号、登录、云同步、多设备冲突解决、广告、埋点、崩溃上报、推送 SDK）均不存在。
- 更新检查不发送设备标识、打卡内容或备份数据，只带应用自报的 `User-Agent`（应用名 + 版本）。
- 应用不做应用内下载与安装；「去更新」只是把 Releases 页交给系统浏览器处理。
- 依赖仅为 AndroidX / Compose / Room / WorkManager / Navigation 等本地库；没有第三方分析服务。
- 所有导出都是用户主动触发的本地文件操作，不会自动上传。
- 应用不读取系统联系人、日历、健康平台或其他应用数据。

## 六、系统备份与设备迁移

`AndroidManifest.xml` 当前为：

```xml
android:allowBackup="true"
android:dataExtractionRules="@xml/data_extraction_rules"
android:fullBackupContent="@xml/backup_rules"
```

而 `backup_rules.xml` 与 `data_extraction_rules.xml` 仍是模板，没有配置 include / exclude。因此：

- Android 系统可能把数据库、`files/` 下的自动备份与崩溃日志纳入云备份或设备迁移。
- 是否启用、备份到哪个账号、是否使用端到端加密，由系统版本、厂商和用户账号设置决定。
- 应用无法单独关闭系统对本应用的备份；若不希望数据进入系统云备份，请在系统「备份」设置中关闭本应用或整体备份。
- 系统恢复可能在重装后自动带回旧数据库；如果你随后又手动导入备份，注意确认哪一份才是最新数据。

这与应用内的「导出备份」是两套机制：前者由操作系统控制，后者由你选择文件位置。

## 七、备份与导出风险

### 7.1 JSON 备份是明文

- 格式为 `daily_trace.backup` v1，包含选项（含回收站）、记录、日期备注、分组、提醒、筛选视图、频率规则和设置。
- 没有加密、没有密码、没有签名校验；`AppSettings.encryption` 字段只是保留，当前未实现。
- 任何拿到文件的人都能读取全部内容，包括单次备注和日期备注。
- 导入只校验格式、版本和字段类型，不验证来源；不要导入不可信的 JSON。

### 7.2 CSV 是明文

- 全量打卡记录，UTF-8 BOM + CRLF，一行一条，便于 Excel 分析。
- 只用于分析，不能恢复完整数据；文本以 `= + - @` 开头时会加单引号防公式注入，但这不是加密。
- 导出后可能被邮件、聊天工具、云盘自动同步或索引。

### 7.3 自动备份的边界

- 自动备份在应用私有目录，普通应用不可读，但卸载即删除，不能替代外部备份。
- 只有最近 5 份，频繁写入会淘汰旧份；重要节点请手动导出。
- 自动备份与应用数据库在同一设备上，设备损坏、丢失或清除数据时可能一起丢失。

### 7.4 恢复的风险

- 导入与「从最近本机备份恢复」都是全量覆盖，不可撤销。
- 备份文件被篡改、字段缺失或版本不符时，导入会失败并保持原库不变；不要通过手工编辑 JSON 来“修复”数据。
- 恢复后建议核对选项数量、记录数量、日期备注、提醒与筛选视图，再继续使用。

## 八、删除、卸载与换机

### 8.1 删除范围

| 操作 | 删除内容 | 历史记录 | 外部文件 |
|------|----------|----------|----------|
| 删除单条记录 | 该条记录 | 其他记录保留 | 不受影响 |
| 批量删除记录 | 所选记录 | 其他记录保留 | 不受影响 |
| 移入回收站 | 选项从使用入口隐藏 | 保留 | 不受影响 |
| 彻底删除选项 | 选项本身 | 保留为只读孤儿记录 | 不受影响 |
| 清除崩溃日志 | `files/crash_logs/` 全部日志 | 不受影响 | 已导出的日志不受影响 |
| 清除应用数据 / 卸载 | 数据库、自动备份、崩溃日志、设置 | 全部删除 | 已导出的 JSON / CSV 保留 |

因此，「彻底删除选项」不等于删除该选项的历史打卡；要清空全部业务数据，请使用系统「清除数据」或卸载。

### 8.2 换机

1. 旧机导出 JSON 备份到可信位置。
2. 用数据线、局域网或加密云盘传输；不要通过公开链接或群聊传输。
3. 新机安装同包名 APK，导入备份，核对数据。
4. 确认无误后删除旧机与传输介质上的副本；旧机可清除应用数据或卸载。

### 8.3 设备丢失

- 应用没有远程擦除、账号定位或云端找回能力。
- 请依赖系统锁屏密码、生物识别、设备查找与磁盘加密。
- 如果开启了系统云备份，数据可能仍在账号云端；请检查账号安全与备份设置。
- 如果曾把明文 JSON / CSV 放在云盘或聊天工具，请尽快删除并更换共享链接。

## 九、崩溃日志与诊断

- 全局未捕获异常会写入 `files/crash_logs/`，最多 10 份；写入失败时静默兜底，不吞掉系统崩溃流程。
- 日志内容：时间、应用版本 / versionCode、设备型号、Android 版本 / SDK、线程名、完整堆栈。
- 不包含打卡正文，但堆栈可能包含类名、文件路径或第三方库信息。
- 日志只在本机；只有你主动「导出崩溃日志」时才会离开应用。
- 设置页的「检查数据」与「修复」只在本机读写数据库，不上传；修复不会删除打卡历史，孤儿记录只统计、不删除。
- 分享日志前建议先打开检查，删除不必要的设备信息或路径。

## 十、安全建议

1. **先导出再操作**：卸载、换机、批量删除、导入前先导出 JSON 备份。
2. **备份放受控位置**：优先放在加密容器、受密码保护的压缩包或可信云盘；不要放公开目录或聊天群。
3. **不要把 JSON / CSV 当普通文件分享**：它们包含完整打卡与备注；分享前先脱敏或只导出必要范围。
4. **锁屏保护**：开启锁屏密码 / 生物识别；在系统设置中隐藏锁屏通知内容，避免提醒和汇总在锁屏泄露。
5. **管理桌面小组件**：共用设备或公共桌面场景下移除小组件，避免选项名称和进度被看到。
6. **定期清理**：删除不再需要的导出文件、旧备份和崩溃日志；应用内崩溃日志可一键清除。
7. **谨慎导入**：只导入自己导出的备份；不要从他人处获取“模板”或修改过的 JSON。
8. **系统备份取舍**：了解系统云备份可能包含应用数据；不需要时在系统设置中关闭本应用备份。
9. **设备与系统**：保持系统更新，不随意 root 或安装来源不明的应用；USB 调试使用后及时关闭。
10. **彻底清除**：清空数据用系统「清除数据」或卸载，并另行清理已导出的文件。
