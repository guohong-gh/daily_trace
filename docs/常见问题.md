# 常见问题

本页按「现象 → 原因 → 处理」整理「日迹」使用、数据、构建与发布中的常见问题。功能入口与完整步骤见 `docs/使用手册.md`；权限与数据风险见 `docs/隐私与数据安全.md`。

> 适用版本：`versionName 1.0.0`、`versionCode 1`、数据库 v6。
> 若问题不在本页，请先记录：应用版本、Android 版本与机型、操作步骤、预期与实际结果、能否复现。不要直接发送真实备份文件或包含隐私的截图。

## 一、安装与启动

### 1. 安装时提示“未知来源”或被系统拦截

**原因**：Android 默认不允许文件管理器或浏览器直接安装应用。

**处理**：在系统弹窗中允许该来源安装，或改用 USB 调试安装：

```powershell
adb install -r app\build\outputs\apk\release\app-release.apk
```

**注意**：只从自己构建或可信来源安装 APK；不要关闭系统的全部安全扫描。

### 2. 覆盖安装失败，提示签名不一致

**原因**：设备上已有同包名应用，但签名与当前 APK 不同。当前 release 使用调试签名，换一台机器构建通常仍是同一调试密钥；换成正式签名后则必然不一致。

**处理**：先导出 JSON 备份，再卸载旧应用，安装新 APK，最后导入备份。

**注意**：卸载会删除应用私有目录中的数据库、自动备份和崩溃日志；没有导出备份就无法恢复。

### 3. 第一次打开没有任何打卡项

**原因**：应用不预置示例选项，只预置 4 个分组（健康、学习、工作、运动）。

**处理**：点今日页空态的「创建选项」，或右下角「＋ 新增」，至少建立一个选项。

**注意**：分组不能新建或改名，只能在编辑选项时从 4 个内置分组中选择。

### 4. 卸载重装后数据不见了

**原因**：Room 数据库、自动备份、崩溃日志都在应用私有目录，卸载时由系统删除。

**处理**：如果之前导出过 JSON 备份，重装后在「设置 → 备份 → 导入备份」中恢复；如果只依赖自动备份，卸载后无法取回。

**注意**：系统云备份或设备迁移可能恢复旧数据，是否发生取决于系统、厂商与账号设置，不能当作可靠备份。

### 5. 界面为什么只有中文

**原因**：当前版本界面文案为硬编码中文，没有界面语言切换。

**处理**：设置中的「日期语言」只改变日期标签（中文 / English / 跟随系统），不会翻译按钮和正文。

### 6. 桌面图标叫什么名字

**处理**：应用名为「日迹」，包名为 `com.gh.daily_trace`；桌面小组件名为「日迹 · 今日」。

## 二、打卡、补卡与计划

### 1. 再点一次复选框，记录为什么消失了

**原因**：布尔型打卡是开关语义。再次点击会删除当天该选项的全部 DONE 记录，而不是写入一条“未完成”。

**处理**：需要保留过程时，改用「部分完成」或先导出备份；误删后只能从备份恢复。

### 2. 计数型连续点「+1」，为什么没有累加

**原因**：新建选项默认「保留多条」，每次 +1 新增一条记录；只有设置为「累加」才会在最新一条 DONE 上累加。

**处理**：编辑选项 →「记录方式」→ 同一天多次打卡规则改为「累加」。

### 3. 填了默认备注，打卡时没有自动带出

**原因**：这是当前实现的已知差异。默认备注只保存在选项里并随备份导出，`CheckInPlanner` 和记录对话框都不会读取它。

**处理**：需要每次备注时，在记录对话框手动填写；或使用「带备注打卡」。

### 4. 部分完成为什么没有让今日进度加一

**原因**：今日页分子只统计 DONE；PARTIAL 不计入“已打卡项数”，但会计入今日数值累计。

**处理**：统计页默认把 PARTIAL 计入完成率（`partialCountsAsDone=true`），所以今日进度和统计完成率可能不同。当前没有应用内开关可改这个口径。

### 5. 想补昨天的卡，入口在哪里

**处理**：进入日历 → 点目标日期 →「补卡」。今日页只能记录今天。

**注意**：

- 补卡受设置中的「补卡上限」限制（禁用 / 1 / 3 / 7 / 14 / 30 天）。
- 超过上限时只显示「标记状态」，只能登记跳过，不能补卡或加计划。
- 未来日期不能补卡，只能「添加计划」。

### 6. 为什么未来日期没有「补卡」

**原因**：补卡只针对过去；未来使用计划（PLANNED），今天使用正常记录。

**处理**：在日历或时间线进入未来日期详情 →「添加计划」。同一选项同一天重复添加会更新最近一条计划。

### 7. 计划到当天会自动变成完成吗

**不会**。计划只是提醒自己当天打算做什么，不计完成；当天仍需正常打卡。时间线也不展示未来计划。

### 8. 「跳过今天」按钮是灰的

**原因**：该选项没有开启「允许跳过 / 请假」。

**处理**：编辑选项 →「频率规则」→ 打开「允许跳过 / 请假」。跳过写入频率规则的跳过日期，不新增记录，不计期望、不中断连续。

### 9. 删除单条记录能撤销吗

**不能**。单条删除、批量删除、筛选视图删除都没有回收站或撤销入口；需要保留时先导出 JSON 备份。

### 10. 删除选项后，历史记录为什么还在

**原因**：选项采用软删除；彻底删除也只删除选项本身，历史记录保留为只读快照，仍可在日期详情、日历和搜索中查看。

**处理**：如果目的是彻底清空所有数据，请使用系统「清除数据」或卸载，而不是只删除选项。

### 11. 停用、归档、移入回收站有什么区别

| 操作 | 效果 | 历史记录 |
|------|------|----------|
| 停用 | 不出现在今日列表、日期详情选择器、统计和小组件 | 保留，可在日期详情 / 日历 / 搜索查看 |
| 归档 | 与停用相同的隐藏范围，但管理页有独立“已归档”分区，可批量取消归档 | 保留，周视图可能保留历史行 |
| 移入回收站 | 从所有打卡入口隐藏，可在回收站恢复或彻底删除 | 保留；彻底删除选项后记录仍为只读孤儿 |
| 彻底删除 | 选项不可恢复 | 历史记录仍保留 |

### 12. 为什么不能新建分组

**原因**：当前只有 4 个种子分组，没有独立的分组增删改页面；分组名称、颜色和顺序固定。

**处理**：编辑选项时选择「不分组」或某个内置分组；分组统计按组内期望日加权。

### 13. 上移 / 下移为什么没有变化

**原因**：排序只对管理页「使用中」列表生效。已停用、已归档项不参与排序。

**处理**：先启用或取消归档，再在「使用中」分区调整顺序。

## 三、统计口径

### 1. 今日页和统计页的“今日完成”数字为什么不同

**原因**：两处分母不同。

- 今日页：分母是当前今日列表中的全部选项，受筛选视图影响，包含配额项和非期望日。
- 统计页：分母是全部“使用中”选项（启用、未归档、未删除），不受今日页筛选影响。

**处理**：对比数字前先确认是否应用了筛选，以及是否有停用 / 归档选项。

### 2. 完成率为什么不是各项百分比的平均

**原因**：分组和总完成率按「完成项次 / 期望项次」加权，不是对每个选项的百分比取平均。

**处理**：查看统计页每项的“完成天数 / 期望天数”；配额项没有日级期望，不进入完成率分母。

### 3. 部分完成到底算不算完成

**默认算**。`partialCountsAsDone` 默认 `true`，PARTIAL 会计入完成率分子；今日页进度仍只算 DONE。当前没有应用内开关。

### 4. 昨天没打卡，连续为什么没断

**原因**：今天尚未打卡时有宽限，不中断当前连续；跳过日也不计期望、不中断连续。

**注意**：宽限只覆盖“今天还没打”，不覆盖昨天及更早的漏打；具体以统计页当前连续为准。

### 5. 「累计」为什么不随范围切换

**原因**：「累计」是全时段总量，不随本周 / 本月 / 近 30 天变化。布尔=完成次数；计数=数值合计；时长按分钟友好化；数值=合计。

### 6. 配额项为什么没有连续和完成率

**原因**：「每月几次」「每周几次」是配额目标，不产生日级期望，因此不进入完成率分母，也不计算连续；统计页单独显示「x/N 次」。

### 7. 归档后统计里为什么找不到这个选项

**原因**：统计只包含使用中选项（启用、未归档、未删除）。停用、归档、回收站选项都不计入。

### 8. 周报 / 月报统计的是哪段时间

- 周报：本周按设置的每周起始日到今天。
- 月报：本月 1 日到今天。
- 上期对比：紧邻的等长时段；完成率按期望日口径，完成项次等按实际完成口径。

### 9. 趋势图的范围跟上面的“统计范围”有关吗

**无关**。趋势独立计算：周模式最近 8 周，月模式最近 6 个月；上方范围只影响分组、选项完成率和连续窗口。

## 四、日历、搜索与筛选

### 1. 日历上的彩点代表什么

彩点是逐选项快照色：DONE / PARTIAL 产点，同项同日只保留一个点，按管理顺序最多 4 个，超出显示「+N」；备注用第三色点。PLANNED / SKIPPED 不产点。

### 2. 为什么只能翻到 1970–2100 年

**原因**：日历翻月、翻周、翻年都限制在 1970-01-01 至 2100-12-31，边界停住不回绕，避免无限分页和越界日期。

### 3. 周视图里为什么还有已归档选项

**原因**：周视图保留已归档选项的历史行，便于回看；回收站选项不作为行。

### 4. 时间线为什么没有未来计划

**原因**：时间线只展示有内容的过去 / 今天，未来计划由月 / 周 / 年视图和日期详情承载。

### 5. 长按空白日期没有摘要

**原因**：长按只对有记录、跳过登记或日期备注的日期弹摘要；空日长按等同点击进入详情。

### 6. 搜索不输入关键词为什么不能浏览

**原因**：当前搜索要求关键词非空，不支持空关键词全量浏览；需要按日期浏览时用日历或时间线。

### 7. 选项改名后，搜索旧名字还能搜到吗

**能**。搜索命中的是记录里的选项名称快照和单次备注，不搜索当前选项名；改名不会改写历史快照。

### 8. 日期备注能被搜索到吗

**能**。搜索同时命中打卡备注、记录中的选项名称快照和日期备注，并可与日期范围组合。

### 9. 应用重启后筛选为什么没了

**原因**：筛选通过导航 `savedStateHandle` 回写今日页，进程被回收或应用重启后重置为未筛选；筛选视图本身仍保存在数据库里，可重新应用。

### 10. 日历为什么没有按“已打卡 / 未打卡”过滤

**原因**：日历只联动筛选的选项 / 分组范围，忽略日级 `dayFilter`，避免“未打卡”把日历清空。应用筛选后顶部会显示“标记已按筛选联动”。

### 11. 删除筛选视图为什么没有确认框

**原因**：当前实现是点击「删除」立即生效。误删后只能重新创建；不会影响打卡数据。

### 12. 筛选编辑器怎么快速全选

选项区和分组区标题行右侧都有「全选 / 清空」切换按钮；区为空时按钮禁用。

## 五、提醒与通知

### 1. 到点没有收到提醒

按顺序检查：

1. 选项是否启用、未归档、未删除，且提醒开关已打开。
2. 是否处于全局暂停（设置 → 提醒）；暂停期间所有提醒和每日汇总都会撤下。
3. Android 13+ 是否授予通知权限；通知渠道是否被关闭。
4. Android 12+ 是否允许“闹钟和提醒”（精确闹钟）；未允许时系统可能延迟。
5. 厂商省电策略是否限制后台；尝试把应用加入白名单。
6. 设备是否刚重启或应用被强制停止；打开一次应用会触发全量重排。

### 2. 提醒总是晚几分钟

**原因**：没有精确闹钟权限时，应用降级为 `setAndAllowWhileIdle`，系统可能延迟；部分厂商的省电策略会进一步延后。

**处理**：在编辑页的权限提示中点「去允许精准提醒」，并在系统设置中允许“闹钟和提醒”。

### 3. 免打扰时段内还是有通知

**原因**：免打扰只把通知降为低优先级“安静”渠道，不是完全不发；通知仍会显示，但通常无声音 / 振动。

**处理**：如果仍有声音，检查系统通知渠道设置是否被改回高优先级，或系统是否忽略了低优先级渠道。

### 4. 「稍后」是多久，能改吗

固定 10 分钟。通知动作「稍后 10 分钟」排一个一次性闹钟，不改变原有每日 / 每周提醒系列；当前没有 UI 修改入口。

### 5. 通知里的「打卡」为什么不能点

**原因**：只有布尔型提醒才有「打卡」动作；计数、时长、数值型需要打开应用记录。

**注意**：通知打卡是幂等的，已完成时不会重复写入；它也不会把已完成改成未完成。

### 6. 每日汇总没有来

检查：

- 设置 → 提醒 →「每日汇总提醒」是否打开（默认关闭）。
- 汇总时刻是否已过；WorkManager 周期任务可能有几分钟偏差。
- 是否处于暂停、通知权限是否关闭；这些情况下 Worker 会静默。
- 是否跨过逻辑日边界；汇总按设置的“新一天开始时间”计算。

### 7. 时区为什么不能改

当前 `AppSettings.timezone` 固定为 `Asia/Shanghai`，没有 UI 修改入口。提醒时刻、每日汇总、CSV 记录时刻都按这个时区解释；跨时区旅行时请注意实际触发时间。

### 8. 重启手机后提醒会丢吗

正常情况下不会：开机、时间变更、时区变更、应用更新都会触发重排；应用启动时也会全量重排一次。若被系统强制停止或厂商限制自启动，可能需要手动打开一次应用。

### 9. 通知和小组件会不会泄露内容

会显示选项名称、完成进度或汇总数量。锁屏预览、通知历史、桌面可见性取决于系统设置和周围环境；敏感场景请在系统设置中隐藏锁屏通知内容，或移除桌面小组件。

## 六、备份、恢复与 CSV

### 1. 导出的备份文件在哪里

通过系统文件选择器（SAF）保存到你选择的位置，应用不会固定写到某个目录，也不需要存储权限。默认文件名 `daily_trace_backup_YYYYMMDD.json`。

### 2. 导入备份会合并还是覆盖

**全量覆盖**。导入会在单个事务内清空并替换选项、记录、日期备注、分组、提醒、筛选视图、频率规则和设置；当前数据不可撤销，导入前建议先导出一份。

### 3. 自动备份存在哪里，卸载后还在吗

存在应用私有目录 `files/backups/`，最多保留最近 5 份；卸载或清除数据会一并删除。它不是应用外部备份，不能替代「导出备份」。

### 4. 备份加密了吗

**没有**。JSON v1 是明文，包含选项（含回收站）、记录、备注、提醒、筛选、频率规则和设置；`encryption` 字段只是保留，当前未实现加密。请把备份放在受控位置。

### 5. 旧版本备份还能导入吗

当前只支持备份格式版本 1。旧备份缺少新字段时会使用默认值（例如日期语言回退中文、周配额为空）；格式或版本不符会报错，库内数据保持不变。

### 6. CSV 能用来恢复吗

**不能**。CSV 只用于 Excel 等表格分析，一行一条记录，不含分组、提醒、筛选、频率规则和设置的完整结构；恢复请用 JSON 备份。

### 7. CSV 用 Excel 打开乱码

CSV 使用 UTF-8 BOM + CRLF，正常情况下 Excel 可直接识别。若仍乱码，请在 Excel 中用「数据 → 从文本/CSV」并选择 UTF-8 导入，不要用本地编码另存。

### 8. CSV 包含哪些列

表头为「日期,记录时间,选项,状态,数值,单位,备注,来源,补卡,时区」，按 `date, createdAt, id` 升序；状态包括完成、部分完成、跳过、计划中，旧 SKIPPED 记录也会导出。

### 9. 「从最近本机备份恢复」和「导入备份」有什么区别

- 从最近本机备份恢复：直接使用 `files/backups/` 中最近一份，不能选文件。
- 导入备份：从系统文件选择器选择任意 JSON。
- 两者都是全量覆盖、不可撤销；没有本机备份时前者按钮禁用。

### 10. 系统云备份会包含日迹数据吗

`AndroidManifest.xml` 中 `allowBackup=true`，`backup_rules.xml` 与 `data_extraction_rules.xml` 仍是模板（没有 include/exclude）。因此系统可能把数据库、私有文件和自动备份纳入云备份或设备迁移，是否发生取决于系统、厂商和用户账号设置，应用无法单独控制。若不希望如此，请在系统备份设置中关闭本应用的云备份。

### 11. 换手机的推荐步骤

1. 旧机：设置 → 备份 →「导出备份」，保存到可信位置。
2. 通过数据线、局域网或加密云盘传输 JSON；不要用公开链接。
3. 新机：安装同包名 APK → 导入备份 → 核对选项、记录、提醒和设置。
4. 确认无误后删除旧机和传输介质上的备份副本。

### 12. 备份文件很大或打开很慢

备份是未压缩的明文 JSON，记录越多文件越大；导入需要解析和单事务写入，数据量大时会慢一些。不要用文本编辑器直接修改备份，字段缺失或类型错误会导致导入失败。

## 七、数据与隐私

### 1. 应用会联网或上传数据吗

不会。Manifest 中没有 `INTERNET` 权限，也没有账号、云同步、广告或分析 SDK。所有业务数据只写入本机 Room 数据库；导出备份 / CSV 是你主动发起的文件操作。

### 2. 为什么只有三个权限

- `POST_NOTIFICATIONS`：Android 13+ 显示提醒和每日汇总。
- `SCHEDULE_EXACT_ALARM`：尽量准点触发提醒。
- `RECEIVE_BOOT_COMPLETED`：重启后恢复提醒调度。

没有存储、位置、通讯录、相机、麦克风或网络权限。导出通过 SAF 授权单个文件 URI，不需要广泛存储权限。

### 3. 数据具体存在哪里

- 数据库：应用私有目录 `databases/daily_trace.db`（可能还有 `-wal` / `-shm`）。
- 自动备份：`files/backups/daily_trace_*.json`，最多 5 份。
- 崩溃日志：`files/crash_logs/crash_*.log`，最多 10 份。
- 导出的 JSON / CSV：你选择的 SAF 位置，离开应用私有目录后不再受应用保护。

普通应用无法直接读取这些私有文件；已 root 的设备、开启 USB 调试的电脑或系统备份可能绕过这一限制。

### 4. 怎样彻底删除所有数据

使用系统「设置 → 应用 → 日迹 → 存储 → 清除数据」，或卸载应用。这样会删除数据库、自动备份和崩溃日志；已经导出到外部的 JSON / CSV 不会被删除，需要你自己清理。

仅删除选项、清空回收站或删除单条记录，都不会删除全部历史；彻底删除选项后历史记录仍以只读快照保留。

### 5. 崩溃日志包含什么

包含应用版本、设备型号、Android 版本、线程名和完整堆栈，用于定位崩溃；不包含打卡正文，但可能包含类名、文件路径等信息。日志只在本机，最多 10 份，可在设置页导出或清除。

### 6. 手机丢失怎么办

应用没有远程擦除或账号定位能力。请依赖系统锁屏、设备查找和磁盘加密；如果开启了系统云备份，备份可能仍在你的账号中。日常建议定期导出加密容器中的 JSON 备份，并开启锁屏。

## 八、构建、测试与发布

### 1. 提示 `gradlew.bat` 不是可识别的命令

PowerShell 中当前目录的可执行文件需要加 `.\`：

```powershell
.\gradlew.bat testDebugUnitTest
```

不要写成 `gradlew.bat testDebugUnitTest`。

### 2. Gradle 报 JDK 版本错误

当前基线：启动 Gradle 使用 JDK 23.0.2，daemon 按 `gradle/gradle-daemon-jvm.properties` 使用 JDK 25（可自动下载）。先确认：

```powershell
java -version
.\gradlew.bat --version
```

若 `local.properties` 缺少 `sdk.dir`，按 `贡献指南.md` 补上本机 SDK 路径；不要提交该文件。

### 3. `adb` 找不到

本机 adb 不一定在 PATH。使用完整路径：

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
```

多设备时必须指定序列号，例如 `-s emulator-5554`，否则可能装到别的模拟器。

### 4. 单元测试失败怎么定位

先只跑失败类：

```powershell
.\gradlew.bat testDebugUnitTest --tests "com.gh.daily_trace.domain.stats.StatsCalculatorTest"
```

再查看 `app\build\reports\tests\testDebugUnitTest\index.html`。时间相关用例应固定 `Asia/Shanghai` 与显式 `epochDay`，不要依赖本机当前时间。

### 5. lint 有警告能提交吗

门禁要求 **0 errors**；当前基线为 0 errors / 17 warnings。新增 warning 必须在批次说明中解释，能修则修；有 error 不得提交。

### 6. release 安装失败或打开崩溃

- 当前 release 使用调试签名，换签名后需要先卸载旧包（会丢数据，先备份）。
- 确认 `assembleRelease` 成功，且安装的是 `app\build\outputs\apk\release\app-release.apk`。
- R8 相关问题查看 `app\build\outputs\mapping\release\mapping.txt`，并在 release 包上走关键路径，不能只测 debug。

### 7. `verify.ps1` 被 PowerShell 执行策略阻止

优先在仓库根目录运行：

```powershell
.\scripts\verify.ps1
```

若被执行策略阻止，可只对本次进程放宽：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\verify.ps1
```

不要为了跑脚本永久关闭系统执行策略。

### 8. `verify.ps1` 失败了怎么办

脚本按「单测 → lint → release」顺序执行，任一阶段失败即停止。先看第一个失败阶段，不要直接重复运行或跳过：

- 单测失败：看 JUnit XML / HTML 报告；
- lint 失败：看 `app\build\reports\lint-results-debug.txt`；
- release 失败：看 Gradle 堆栈与 R8 配置；
- 指标解析失败：确认测试 XML、lint txt 和 APK 路径存在。

### 9. 项目有 CI 吗

当前没有 CI。质量门禁是本地 `.\scripts\verify.ps1` 加 AVD 手工走查；提交前必须两者都完成，且工作区不含 APK、`build/`、`local.properties`、`.idea/`、崩溃日志或真实备份。

## 九、仍然无法解决

请提供以下信息，便于定位：

1. 应用版本（设置 → 关于）、Android 版本、机型 / AVD 名称。
2. 复现步骤、预期结果、实际结果、是否必现。
3. 相关页面截图（避免包含敏感备注）。
4. 如果是崩溃：设置 → 诊断与修复 →「导出崩溃日志」；如果是提醒：`adb shell dumpsys alarm` 与通知渠道状态。
5. 如果是构建：完整命令、Gradle 首个错误、`java -version` 与 `.\gradlew.bat --version`。
