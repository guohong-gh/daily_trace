# 数据格式说明

本文记录「日迹」的持久化格式：Room 数据库、备份 JSON v1、CSV 导出，以及升级时的兼容规则。改 schema、备份或 CSV 前，先读本文与 `AGENTS.md` 的硬约束。

> 基线：数据库 v6，`versionName 1.0.0`。格式事实来自 `data/`、`backup/`、`domain/csv/` 与 `app/schemas/`。

## 一、数据库

### 1.1 位置与版本

- 数据库名：`daily_trace.db`
- 应用私有目录：`/data/data/com.gh.daily_trace/databases/`（实际路径由 Android 管理）
- Room 版本：`6`
- schema 导出：`app/schemas/com.gh.daily_trace.data.DailyTraceDatabase/1.json` ～ `6.json`
- 日志模式：Room 默认（通常为 WAL），可能同时存在 `-wal` / `-shm` 文件
- 升级策略：显式 `Migration`，禁止 destructive fallback

### 1.2 时间口径

| 名称 | 类型 | 含义 |
|------|------|------|
| 逻辑日 `date` | INTEGER | `epochDay`，即 1970-01-01 起的天数；由 `DayClock` 按 `AppSettings.timezone` 与 `startOfDay` 换算 |
| 时间戳 `createdAt` / `updatedAt` / `exportedAt` / `pausedUntil` | INTEGER | Unix epoch 毫秒（UTC 绝对时刻） |
| 提醒时刻 `time` / `dndStart` / `dndEnd` / `dailySummaryTime` | INTEGER | 当地“距 0 点分钟数”，0–1439；按 `settings.timezone` 解释 |
| 时区 `timezone` | TEXT | IANA ID，如 `Asia/Shanghai`；记录创建时写入记录行 |

逻辑日示例：默认 `startOfDay=4`、`Asia/Shanghai` 下，凌晨 03:59 仍算前一天，04:00 起算新一天。跨逻辑日的页面刷新依赖 `LifecycleResumeEffect`。

### 1.3 表结构

#### `check_items`（打卡选项）

| 列 | 类型 | 可空 | 说明 |
|----|------|------|------|
| `id` | INTEGER PK | 否 | 自增 |
| `name` | TEXT | 否 | 选项名称 |
| `color` | INTEGER | 否 | ARGB 颜色 |
| `icon` | TEXT | 否 | emoji 或图标标识，默认空串 |
| `type` | TEXT | 否 | `CheckType` 枚举名 |
| `unit` | TEXT | 否 | 单位，默认空串 |
| `targetValue` | REAL | 是 | 目标值；空表示只记录 |
| `defaultNote` | TEXT | 否 | 选项级默认备注（第一层备注） |
| `groupId` | INTEGER | 是 | 分组 id；空 = 未分组 |
| `multiRecordRule` | TEXT | 否 | `MERGE` / `ACCUMULATE` / `KEEP_MULTIPLE` |
| `sort` | INTEGER | 否 | 管理顺序，越小越靠前 |
| `enabled` | INTEGER | 否 | 0/1；停用后不出现在打卡列表 |
| `archived` | INTEGER | 否 | 0/1；归档只从打卡列表隐藏 |
| `deletedAt` | INTEGER | 是 | 非空 = 在回收站（软删除） |
| `createdAt` | INTEGER | 否 | 创建时刻 |
| `updatedAt` | INTEGER | 否 | 更新时刻 |

索引：`groupId`。

#### `check_records`（打卡记录）

| 列 | 类型 | 可空 | 说明 |
|----|------|------|------|
| `id` | INTEGER PK | 否 | 自增 |
| `itemId` | INTEGER | 否 | 选项 id；选项彻底删除后可能成为孤儿记录 |
| `date` | INTEGER | 否 | 逻辑日 epochDay |
| `value` | REAL | 是 | 布尔=1.0；计数/时长/数值为具体量；计划可为空 |
| `unit` | TEXT | 否 | 记录时的单位快照 |
| `note` | TEXT | 否 | 单次打卡备注（第二层备注） |
| `status` | TEXT | 否 | `DONE` / `PARTIAL` / `SKIPPED` / `PLANNED` |
| `source` | TEXT | 否 | `MANUAL` / `WIDGET` / `NOTIFICATION` / `IMPORT` |
| `isBackfill` | INTEGER | 否 | 0/1；补卡标记 |
| `timezone` | TEXT | 否 | 创建记录时的时区 ID |
| `createdAt` | INTEGER | 否 | 创建时刻 |
| `updatedAt` | INTEGER | 否 | 更新时刻 |
| `itemNameSnapshot` | TEXT | 否 | 选项名称快照 |
| `itemColorSnapshot` | INTEGER | 否 | 选项颜色快照 |
| `itemIconSnapshot` | TEXT | 否 | 选项图标快照 |

索引：`date`、`itemId`、`(itemId, date)`。

历史展示必须用快照字段，不能回查 `check_items` 的当前名称/颜色/图标。

#### `day_notes`（日期整体备注）

| 列 | 类型 | 可空 | 说明 |
|----|------|------|------|
| `date` | INTEGER PK | 否 | 逻辑日 epochDay，一天一条 |
| `note` | TEXT | 否 | 备注正文；空串在业务上视为删除 |
| `createdAt` | INTEGER | 否 | 创建时刻 |
| `updatedAt` | INTEGER | 否 | 更新时刻 |

#### `groups`（分组）

| 列 | 类型 | 可空 | 说明 |
|----|------|------|------|
| `id` | INTEGER PK | 否 | 自增 |
| `name` | TEXT | 否 | 分组名 |
| `color` | INTEGER | 否 | ARGB 颜色 |
| `sort` | INTEGER | 否 | 排序 |

种子数据：健康、学习、工作、运动。当前无独立分组管理 UI；只能在编辑选项时选择分组。

#### `reminders`（提醒）

| 列 | 类型 | 可空 | 说明 |
|----|------|------|------|
| `id` | INTEGER PK | 否 | 自增 |
| `itemId` | INTEGER | 否 | 选项 id；唯一索引，一个选项至多一条 |
| `time` | INTEGER | 否 | 提醒时刻（分钟数） |
| `repeat` | TEXT | 否 | `DAILY` / `WEEKDAYS` / `WEEKLY` |
| `daysOfWeek` | TEXT | 否 | `WEEKLY` 生效；逗号分隔的 ISO 星期（1=周一…7=周日） |
| `enabled` | INTEGER | 否 | 0/1 |
| `snooze` | INTEGER | 否 | 稍后提醒分钟数，默认 10；当前无 UI 修改入口 |
| `dndStart` | INTEGER | 是 | 免打扰开始分钟；空 = 未启用 |
| `dndEnd` | INTEGER | 是 | 免打扰结束分钟；支持跨午夜 |
| `updatedAt` | INTEGER | 否 | 更新时刻 |

唯一索引：`itemId`。

#### `filter_views`（保存的筛选视图）

| 列 | 类型 | 可空 | 说明 |
|----|------|------|------|
| `id` | INTEGER PK | 否 | 自增 |
| `name` | TEXT | 否 | 视图名称 |
| `mode` | TEXT | 否 | `ALL` / `SELECTED` |
| `itemIds` | TEXT | 否 | 逗号分隔的选项 id |
| `groupIds` | TEXT | 否 | 逗号分隔的分组 id |
| `logic` | TEXT | 否 | `ANY` / `ALL` |
| `dayFilter` | TEXT | 否 | `ALL` / `RECORDED` / `UNRECORDED` |
| `createdAt` | INTEGER | 否 | 创建时刻 |

#### `frequency_rules`（频率规则）

| 列 | 类型 | 可空 | 说明 |
|----|------|------|------|
| `id` | INTEGER PK | 否 | 自增 |
| `itemId` | INTEGER | 否 | 选项 id；唯一索引 |
| `type` | TEXT | 否 | `DAILY` / `DAYS_OF_WEEK` / `TIMES_PER_MONTH` / `TIMES_PER_WEEK` / `CUSTOM` |
| `daysOfWeek` | TEXT | 否 | `DAYS_OF_WEEK` 生效；逗号分隔 ISO 星期 |
| `timesPerMonth` | INTEGER | 是 | 月度配额目标（1–31） |
| `timesPerWeek` | INTEGER | 是 | 周度配额目标（1–7） |
| `intervalDays` | INTEGER | 是 | `CUSTOM` 间隔 N 天（1–90） |
| `anchorEpochDay` | INTEGER | 是 | `CUSTOM` 锚点日（epochDay） |
| `targetValue` | REAL | 是 | 预留目标值，当前无编辑入口 |
| `allowSkip` | INTEGER | 否 | 0/1；是否允许跳过/请假 |
| `skipDates` | TEXT | 否 | 逗号分隔的跳过日 epochDay |
| `updatedAt` | INTEGER | 否 | 更新时刻 |

唯一索引：`itemId`。

#### `app_settings`（单行设置）

| 列 | 类型 | 可空 | 默认值 / 说明 |
|----|------|------|----------------|
| `id` | INTEGER PK | 否 | 恒为 1 |
| `theme` | TEXT | 否 | `SYSTEM` / `LIGHT` / `DARK`，默认 `SYSTEM` |
| `dynamicColor` | INTEGER | 否 | 0/1，默认 0；Android 12+ 可开启 |
| `weekStart` | INTEGER | 否 | 1=周一…7=周日，默认 1 |
| `startOfDay` | INTEGER | 否 | 0–6，默认 4 |
| `timezone` | TEXT | 否 | 默认 `Asia/Shanghai`；当前无 UI 修改入口 |
| `dateLanguage` | TEXT | 否 | `SYSTEM` / `ZH` / `EN`，默认 `ZH` |
| `dateFormat` | TEXT | 否 | `AUTO` / `YMD` / `MDY` / `DMY`，默认 `AUTO` |
| `colorBlindMode` | INTEGER | 否 | 0/1，默认 0；保留字段，无 UI / 无行为 |
| `maxBackfillDays` | INTEGER | 否 | 默认 7；0 = 禁止补卡 |
| `partialCountsAsDone` | INTEGER | 否 | 默认 1；当前无 UI 开关 |
| `autoBackup` | INTEGER | 否 | 默认 0 |
| `autoBackupIntervalDays` | INTEGER | 否 | 默认 7；可选 1/3/7/15/30 |
| `encryption` | INTEGER | 否 | 默认 0；保留字段，未实现加密 |
| `pausedUntil` | INTEGER | 是 | 暂停截止时刻（epoch millis）；空 = 未暂停 |
| `dailySummaryEnabled` | INTEGER | 否 | 默认 0 |
| `dailySummaryTime` | INTEGER | 否 | 默认 1260（21:00） |

### 1.4 枚举值

| 枚举 | 取值 |
|------|------|
| `CheckType` | `BOOLEAN`、`COUNT`、`DURATION`、`VALUE` |
| `RecordStatus` | `DONE`、`PARTIAL`、`SKIPPED`、`PLANNED` |
| `RecordSource` | `MANUAL`、`WIDGET`、`NOTIFICATION`、`IMPORT` |
| `MultiRecordRule` | `MERGE`、`ACCUMULATE`、`KEEP_MULTIPLE` |
| `FilterMode` | `ALL`、`SELECTED` |
| `FilterLogic` | `ANY`、`ALL` |
| `DayFilter` | `ALL`、`RECORDED`、`UNRECORDED` |
| `FrequencyType` | `DAILY`、`DAYS_OF_WEEK`、`TIMES_PER_MONTH`、`TIMES_PER_WEEK`、`CUSTOM` |
| `RepeatType` | `DAILY`、`WEEKDAYS`、`WEEKLY` |
| `ThemeMode` | `SYSTEM`、`LIGHT`、`DARK` |
| `DateLanguage` | `SYSTEM`、`ZH`、`EN` |
| `DateFormat` | `AUTO`、`YMD`、`MDY`、`DMY` |

枚举以 `name` 持久化。**不要重命名或删除枚举常量**；如必须变更，先写迁移并保证旧库、旧备份可读。

### 1.5 迁移记录

| 迁移 | 变更 | 旧数据 |
|------|------|--------|
| 1→2 | `frequency_rules` 加 `intervalDays`、`anchorEpochDay`；`reminders` 加 `daysOfWeek` | 旧 WEEKLY 提醒的星期从对应频率规则复制 |
| 2→3 | `app_settings` 加 `pausedUntil` | 默认 NULL，即未暂停 |
| 3→4 | `app_settings` 加 `dailySummaryEnabled`、`dailySummaryTime` | 默认 0 / 1260 |
| 4→5 | `app_settings` 加 `dateLanguage`、`dateFormat` | 默认 `ZH` / `AUTO` |
| 5→6 | `frequency_rules` 加 `timesPerWeek` | 默认 NULL；旧规则行为不变 |

新增 schema 的步骤：

1. 改实体；
2. 升 `@Database(version = N)`；
3. 写 `Migration(N-1, N)`；
4. 加入 `.addMigrations(...)`；
5. 构建导出 `app/schemas/.../N.json`；
6. 补迁移/往返测试；
7. 更新本文档与备份兼容说明。

## 二、备份 JSON v1

### 2.1 文件与位置

- 用户导出：设置 → 备份 → 导出备份，通过 SAF 选择位置；默认文件名 `daily_trace_backup_YYYYMMDD.json`（按系统默认时区取日期）。
- 自动备份：应用私有目录 `files/backups/`，文件名 `daily_trace_yyyyMMdd_HHmmss.json`，保留最近 **5** 份。
- 手动「立即备份到本机」忽略自动备份开关与间隔，直接写一份。
- 触发：应用启动、退到后台时按间隔检查；间隔为 1/3/7/15/30 天。
- 备份为**明文 JSON**，未加密；`AppSettings.encryption` 字段保留但未实现。

### 2.2 根结构

```json
{
  "format": "daily_trace.backup",
  "version": 1,
  "exportedAt": 1760000000000,
  "items": [],
  "records": [],
  "dayNotes": [],
  "groups": [],
  "reminders": [],
  "filterViews": [],
  "frequencyRules": [],
  "settings": {}
}
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `format` | string | 固定 `daily_trace.backup`；不匹配即拒绝 |
| `version` | int | 当前为 1；支持 1..1 |
| `exportedAt` | long | 导出时刻（epoch millis） |
| `items` | array | 选项，含回收站 |
| `records` | array | 全部打卡记录 |
| `dayNotes` | array | 日期备注 |
| `groups` | array | 分组 |
| `reminders` | array | 提醒 |
| `filterViews` | array | 筛选视图 |
| `frequencyRules` | array | 频率规则 |
| `settings` | object / null | 设置快照；null 时导入保留当前设置 |

### 2.3 对象字段

字段与实体属性一一对应，枚举存 `name`，列表存数组，可空字段存 `null`。解码器对缺失数组返回空列表，对缺失可选字段使用默认值；必需字段缺失会抛 `BackupFormatException`。

| 对象 | 字段 |
|------|------|
| item | `id`、`name`、`color`、`icon`、`type`、`unit`、`targetValue`、`defaultNote`、`groupId`、`multiRecordRule`、`sort`、`enabled`、`archived`、`deletedAt`、`createdAt`、`updatedAt` |
| record | `id`、`itemId`、`date`、`value`、`unit`、`note`、`status`、`source`、`isBackfill`、`timezone`、`createdAt`、`updatedAt`、`itemNameSnapshot`、`itemColorSnapshot`、`itemIconSnapshot` |
| dayNote | `date`、`note`、`createdAt`、`updatedAt` |
| group | `id`、`name`、`color`、`sort` |
| reminder | `id`、`itemId`、`time`、`repeat`、`daysOfWeek`、`enabled`、`snooze`、`dndStart`、`dndEnd`、`updatedAt` |
| filterView | `id`、`name`、`mode`、`itemIds`、`groupIds`、`logic`、`dayFilter`、`createdAt` |
| frequencyRule | `id`、`itemId`、`type`、`daysOfWeek`、`timesPerMonth`、`timesPerWeek`、`intervalDays`、`anchorEpochDay`、`targetValue`、`allowSkip`、`skipDates`、`updatedAt` |
| settings | `theme`、`dynamicColor`、`weekStart`、`startOfDay`、`timezone`、`dateLanguage`、`dateFormat`、`colorBlindMode`、`maxBackfillDays`、`partialCountsAsDone`、`autoBackup`、`autoBackupIntervalDays`、`encryption`、`pausedUntil`、`dailySummaryEnabled`、`dailySummaryTime` |

### 2.4 导入语义

1. 读取用户选择的 JSON 文本；
2. `BackupCodec.parse` 校验 `format` / `version` / 必需字段；失败抛 `BackupFormatException`，**库内数据不动**；
3. `BackupManager.importJson` 在**单事务**内执行：
   - 清空 `check_records`、`check_items`、`day_notes`、`groups`、`reminders`、`filter_views`、`frequency_rules`；
   - 按备份顺序插入各表（保留原 id）；
   - `settings` 非 null 时 upsert；为 null 时保留当前设置；
4. 任一写入失败整体回滚；
5. 成功后重排提醒与每日汇总，刷新界面。

注意：导入是**全量覆盖**，不是合并；导入前会二次确认。备份包含回收站选项，但不包含备份文件自身、崩溃日志、系统通知。

### 2.5 兼容规则

- 新增字段优先做成可选字段并给默认值，保持 `version = 1`；只有破坏性变化才升备份版本。
- 旧备份缺新字段时回退默认值（例如日期语言 `ZH`、格式 `AUTO`、`partialCountsAsDone=true`）。
- 不重命名已持久化的枚举值；不改变字段含义。
- 不删除旧字段，除非提供迁移与兼容测试。
- 任何格式变化必须同步本文档、`M5BackupTest` 兼容用例与 `docs/决策记录.md`。

## 三、CSV 导出

### 3.1 用途与范围

- 入口：设置 → 备份 → 导出 CSV（打卡记录）。
- 内容：**全部打卡记录**，一行一条；不做日期范围筛选。
- 用途：Excel 等表格分析；**不承担完整恢复职责**。完整恢复使用 JSON 备份。
- 默认文件名：`daily_trace_records_YYYYMMDD.csv`（按 `settings.timezone` 取日期）。

### 3.2 编码与格式

- UTF-8 **带 BOM**（`\uFEFF`），便于 Excel 识别中文。
- 换行：CRLF（`\r\n`）。
- 文本按 RFC 4180 转义：含逗号、双引号、CR、LF 时整体加双引号，内部双引号翻倍。
- 对以 `=`、`+`、`-`、`@` 开头的用户文本（选项快照、单位、备注、时区）加单引号前缀，防止表格公式注入。
- 数值：整数不带 `.0`，小数去尾零；空值留空。
- 排序：`date ASC, createdAt ASC, id ASC`。

### 3.3 表头与列含义

```text
日期,记录时间,选项,状态,数值,单位,备注,来源,补卡,时区
```

| 列 | 说明 |
|----|------|
| 日期 | 逻辑日 ISO `yyyy-MM-dd` |
| 记录时间 | `createdAt` 按 `settings.timezone` 格式化为 `yyyy-MM-dd HH:mm:ss` |
| 选项 | `itemNameSnapshot`（历史名称，不是当前名称） |
| 状态 | `完成` / `部分完成` / `跳过` / `计划中` |
| 数值 | 记录值；布尔通常为 `1`；空值留空 |
| 单位 | 记录时的单位快照 |
| 备注 | 单次打卡备注 |
| 来源 | `手动` / `小组件` / `通知` / `导入` |
| 补卡 | `是` / `否` |
| 时区 | 记录行 `timezone` 字段（创建时区），不是导出时设置时区 |

### 3.4 示例

```csv
日期,记录时间,选项,状态,数值,单位,备注,来源,补卡,时区
2026-10-19,2026-10-19 08:30:00,跑步,完成,3,公里,晨跑,手动,否,Asia/Shanghai
2026-10-19,2026-10-19 21:10:00,阅读,部分完成,15,分钟,,手动,否,Asia/Shanghai
```

## 四、诊断与修复涉及的数据

设置 → 诊断与修复可执行：

- 检查孤立频率规则 / 提醒（所属选项不存在）；
- 无效分组引用（`groupId` 指向不存在的分组，置空）；
- 空日期备注（删除）；
- 筛选视图失效 id（清理引用）；
- 缺失或越界设置（重建默认 / 夹到合法范围）；
- `PRAGMA quick_check` 报告数据库完整性；
- 从 `files/backups/` 最近一份自动备份覆盖恢复。

修复口径：

- **不删除打卡历史**；选项彻底删除后的孤儿记录保留只读展示，仅在报告中计数。
- 修复只处理可由数据自身推导的不一致，不做“猜测性补数据”。
- 大面积异常优先用备份恢复，不要反复手工改库。

## 五、数据安全边界

- 数据库、自动备份、崩溃日志都在应用私有目录；未 root 的设备其他应用无法直接读取。
- 用户导出的 JSON / CSV 由 SAF 写到用户选择的位置，离开应用私有目录后不受应用保护。
- 备份为明文，不含加密；请把导出文件放在受控位置。
- Manifest `allowBackup=true`，且系统备份规则文件仍为模板；在用户开启系统云备份/换机迁移时，应用数据可能被操作系统纳入备份，具体取决于系统与厂商。详见 `docs/隐私与数据安全.md`。
- 卸载应用会删除私有数据；系统备份是否可恢复取决于用户设置。
