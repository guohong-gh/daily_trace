# 发布流程

本文说明「日迹」从代码到可安装 release 包的固定流程、质量门禁、装机冒烟、签名与回滚注意事项。CI 承担单测 / lint / release 构建与联网范围校验（`INTERNET` 必须声明、源码主机仅限 `api.github.com` / `github.com`），走查、截图与发布决策仍在本机完成并留下记录。

> 当前基线：`versionName 1.0.0`、`versionCode 10000`、数据库 v6、release 开启 R8、release 使用自建 keystore 正式签名。
> 签名参数从本机 `keystore.properties` 读取，缺失时 release 构建直接失败，不会回退调试签名，见第五节。

## 一、版本与发布事实

| 项 | 当前值 | 说明 |
|----|--------|------|
| 包名 | `com.gh.daily_trace` | 不随应用名变化 |
| 应用名 | 日迹 | `strings.xml` 的 `app_name` |
| versionName | `1.0.0` | 用户可见版本 |
| versionCode | `10000` | 每次对外发布必须递增 |
| 数据库版本 | `6` | Room `version = 6`，显式迁移 |
| minSdk | 24 | Android 7.0 |
| target / compileSdk | 37 | 当前工具链 |
| release 签名 | 自建 keystore 正式签名 | 参数来自本机 `keystore.properties`（不入库） |
| R8 | 开启 | `optimization { enable = true }` |
| 产物 | `app\build\outputs\apk\release\app-release.apk` | 不提交仓库 |
| 分发渠道 | Gitee / GitHub 仓库 + Release APK | GitHub Actions 门禁；无应用商店发布 |

版本号规则：

- `versionCode` 单调递增、只增不减；每次对外发布（含热修复）必须比上一版大。
- 首个对外发布包 `1.0.0` 直接使用 **10000**；此后统一按 `major * 10000 + minor * 100 + patch` 计算，例如 `1.2.3 → 10203`、`2.0.0 → 20000`；留出的间隔便于插入补丁版而不破坏顺序。
- `versionName` 遵循语义化版本：不兼容的数据/行为变化升主版本，兼容功能升次版本，修复升补丁版本。
- 数据库版本与 `versionName` 独立；schema 变化必须升 Room 版本并写迁移。
- 签名证书一旦对外发布不可更换：更换后老用户无法覆盖升级，只能卸载（丢数据）或另做迁移方案。

## 二、发布前检查

1. 确认本批次范围与验收标准，必要时更新 `docs/需求差距与验收矩阵.md`。
2. 确认没有未登记的 schema、备份、CSV、权限或依赖变化。
3. 确认 `local.properties`、`.idea/`、`build/`、APK、真实备份没有进入暂存区。
4. 确认工作区没有他人未提交的改动；不要替别人提交。
5. 确认测试与走查所需 AVD 可用（`Medium_Phone_API_37.0`）。

## 三、固定发布步骤

### 3.1 单测

```powershell
.\gradlew.bat testDebugUnitTest
```

要求：全部通过。记录测试总数、失败数与新增用例；不要只说“测试通过”。

### 3.2 lint

```powershell
.\gradlew.bat lintDebug
```

要求：**0 errors**。warning 数量与基线对比；新增 warning 必须解释或修复。

### 3.3 release 构建

```powershell
.\gradlew.bat assembleRelease
```

要求：R8 下构建成功。若本批涉及反射、序列化、Room、WorkManager、Receiver、Widget，必须装机冒烟，不能只看编译通过。

构建后核对签名（证书必须是自建证书，不能是 `CN=Android Debug`）：

```powershell
$apksigner = "$env:LOCALAPPDATA\Android\Sdk\build-tools\36.0.0\apksigner.bat"
& $apksigner verify --print-certs app\build\outputs\apk\release\app-release.apk
```

期望输出包含 `Signer #1 certificate DN: CN=Daily Trace, O=Daily Trace, C=CN` 与固定指纹（SHA-256 `aba3c3ec…0391c`，完整值见 `docs/决策记录.md` D57）。指纹变化意味着更换了签名，必须停下排查。

### 3.4 一键门禁

```powershell
.\scripts\verify.ps1
```

要求：输出 `VERIFY PASSED`，并记录：

- Tests：total / passed / failed / errors / skipped；
- Lint：errors / warnings；
- Release：字节数与 MB；
- APK 路径。

`verify.ps1` 只做单测、lint、release 构建与指标汇总，不会安装 APK、不会跑模拟器走查、不会跑 `androidTest`。手工走查仍是发布前必做项。

### 3.4.1 CI 产物与下载

GitHub Actions 的 `quality-gate` 工作流在推送 / PR 时执行同一套门禁（单测、lint、release 构建、联网范围校验），并把构建好的 APK 上传为构建产物。

下载方式：

1. 打开仓库的 **Actions** 页面，点进目标运行；
2. 拉到页面底部 **Artifacts** 区域，下载 `daily-trace-release-apk`；
3. 解压得到 `app-release.apk`。

注意：

- 该包使用工作流内临时生成的一次性 keystore 签名（`CN=CI Build Only`），**只用于验证构建可完成，不能对外分发**；
- 对外发布包必须在本机用 `keystore.properties` 中的正式签名构建，签名主体为 `CN=Daily Trace`；
- CI 产物保留期跟随仓库 Artifact 设置，不作为长期归档。

### 3.5 安装 release 包

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb devices
& $adb -s emulator-5554 install -r app\build\outputs\apk\release\app-release.apk
& $adb -s emulator-5554 shell am start -n com.gh.daily_trace/.MainActivity
```

要求：

- 覆盖安装后能启动，无启动崩溃；
- 旧数据保留（若本批有 schema 变更，重点验证迁移）；
- 通知权限、精确闹钟、组件等系统集成仍可用。

### 3.6 发布冒烟清单

至少完成：

- [ ] 冷启动进入今日页，无崩溃、无明显卡顿。
- [ ] 新建 / 编辑 / 打卡 / 删除一条记录。
- [ ] 日期详情打开、备注保存、补卡或计划入口可用。
- [ ] 日历月 / 周 / 年 / 时间线至少各打开一次。
- [ ] 搜索一个关键词，命中结果可进详情。
- [ ] 统计页范围、分组、趋势、周期报告可显示。
- [ ] 设置页可打开；主题 / 日期设置能立即生效。
- [ ] 导出备份成功；如本批涉及导入，执行一次覆盖导入（先备份）。
- [ ] 如涉及提醒：授权通知与精确闹钟，触发一次通知，验证动作。
- [ ] 如涉及组件：添加组件，验证进度与快捷打卡。
- [ ] 如涉及诊断：检查数据、崩溃日志入口可用。

### 3.7 升级 / 迁移验证

有 schema 变更时：

1. 在旧版本上准备演示数据（选项、记录、备注、提醒、筛选）。
2. 用 `install -r` 覆盖安装新 release（同签名）。
3. 启动后逐项核对数据完整、无崩溃。
4. 如可安全拉库，核对 `user_version` 与新列；不要在真实用户数据上做实验。
5. 迁移只能向前：新库被旧 APK 打开可能失败，回滚前必须备份并清数据。

### 3.8 文档同步

发布前至少确认：

- `README.md` 的命令与版本事实正确；
- `docs/使用手册.md` 覆盖本批用户可见变化；
- `docs/项目状态与计划.md` 增加本批记录与验证数据；
- `docs/需求差距与验收矩阵.md` 更新状态；
- `docs/决策记录.md` 登记 D50+ 新决策；
- `docs/数据格式说明.md` 在 schema / 备份 / CSV 变化时同步；
- `变更日志.md` 记录用户可见变化与已知限制。

### 3.9 提交与推送

一个批次一个提交：

```powershell
git status --short
git diff --check
git add <本批文件>
git commit -m "docs: 中文文档体系与软件使用手册"
git push origin main
```

提交信息使用 `类型: 中文摘要`，类型见 `AGENTS.md`。不要提交 APK、`build/`、`local.properties`、`.idea/`、崩溃日志、真实备份。

不要在未获明确要求时创建 tag 或 Gitee/GitHub Release。

## 五、签名与 keystore 管理

release 一律使用自建 keystore 签名，**不存在回退 debug 签名的分支**：`app/build.gradle.kts` 在 configuration 阶段读取仓库根 `keystore.properties`，缺失时任何 release 任务（`assembleRelease` / `bundleRelease` / `assemble` / `build` / `bundle`）立即失败并提示缺文件；单测、lint、debug 构建不依赖该文件。

本机现状（2026-11-09）：

| 项 | 值 |
|----|----|
| keystore 路径 | `keystore\daily_trace-release.jks`（被 `.gitignore` 忽略） |
| 类型 / 算法 | PKCS12 / RSA 4096，有效期 10000 天 |
| alias | `daily_trace` |
| 口令 | 32 位强随机值，只存在本机 `keystore.properties`（`storePassword` / `keyPassword` 同值） |
| 证书主体 | `CN=Daily Trace, O=Daily Trace, C=CN`（不使用个人信息） |
| 证书 SHA-256 | `aba3c3eca6492c3b7ce7d41700d912204fd6b02e9f826346c66a19f69b10391c` |

`keystore.properties` 格式（不入库）：

```properties
storeFile=keystore/daily_trace-release.jks
storePassword=<本机口令>
keyAlias=daily_trace
keyPassword=<本机口令>
```

重新生成（仅当确认尚未对外分发，或需要新项目签名时）：

```powershell
$keytool = "C:\Program Files\Java\jdk-23\bin\keytool.exe"
& $keytool -genkeypair -keystore keystore\daily_trace-release.jks -storetype PKCS12 `
  -alias daily_trace -keyalg RSA -keysize 4096 -validity 10000 `
  -dname "CN=Daily Trace, O=Daily Trace, C=CN"
& $keytool -list -v -keystore keystore\daily_trace-release.jks -alias daily_trace
```

强制要求：

1. **必须离线备份 keystore 与口令**（至少两份、异地存放）。keystore 丢失 = 永久无法发布可覆盖升级的新版本，老用户只能卸载重装并丢数据。
2. 不要把 keystore、`keystore.properties`、口令写进仓库、Issue、CI 日志或截图；`.gitignore` 已忽略 `keystore/` 与 `keystore.properties`。
3. 证书指纹（SHA-256）与保管人写入发布记录；对外发布后再更换签名属于破坏性变更。
4. CI 无法也不应持有正式私钥：工作流使用一次性生成的临时 keystore 仅做「能否签名构建」验证，产物不可对外分发。

## 六、回滚

- 保留上一版 APK 与对应 JSON 备份。
- 同签名可 `install -r` 回滚；不同签名需要卸载，先导出备份。
- 数据库迁移是向前的：旧 APK 打开新库可能失败。回滚到旧版本前，先导出数据；必要时清空应用数据后再导入旧版本可读的备份。
- 不要用“删除数据库”作为常规回滚手段；会丢失全部历史。

## 七、发布完成定义

- [ ] 单测全绿，测试数记录。
- [ ] lint 0 error。
- [ ] release 构建成功，R8 下关键路径已冒烟。
- [ ] `verify.ps1` 输出 `VERIFY PASSED`。
- [ ] 模拟器走查完成，截图与记录入库。
- [ ] 文档、验收矩阵、决策记录、变更日志同步。
- [ ] 单批提交并推送 `origin main`。
- [ ] 工作区仅剩既有未跟踪目录，无构建产物。
